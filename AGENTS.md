# AGENTS.md

## Layout

- `src/gen/` — protobuf/gRPC bindings, generated by `buf generate` and committed (`@generated`, excluded from `cargo fmt` via `include!`). Never hand-edit.
- `src/lib.rs` — re-exports; `pub mod proto` is the generated code.
- `src/state.rs` — `StateCache`: the normalized in-memory snapshot (units/groups/simulation/locations) the gRPC services read from. `Unit.group_id` is the only place group membership is recorded.
- `src/commands.rs` — domain `Command` enum, `CommandSink` trait (implemented by engines), `Dispatcher` (tracks in-flight commands until acked or timed out).
- `src/services/` — tonic service impls; thin wrappers over `StateCache`/`Dispatcher`.
- `src/server.rs` — `ServerConfig`, `serve()` (embed in an existing runtime), `ServerHandle::spawn()` (owns its own runtime + thread; what engine plugins use).

## Regenerating protos

```sh
buf generate
```

`buf.gen.yaml`'s `inputs` pins a specific [BSR](https://buf.build/voron-simulations/minerva) commit rather than tracking `main`, so a protocol change only takes effect here once you deliberately bump it. To pick up a new protocol commit: bump the `module:` ref in `buf.gen.yaml`, regenerate, and commit the diff in `src/gen/`.

## Testing

- `cargo test` — unit tests (`src/*.rs`) plus `tests/grpc.rs` (real `ServerHandle` over a real socket).
- `cargo llvm-cov --ignore-filename-regex '^src/gen/'` — coverage, excluding generated code.
- `cargo bench` — `benches/state.rs`; `cargo bench --no-run` just checks it compiles (CI does this, not a full run).

## Gotchas

- `ServerHandle::shutdown`/`Drop` waits for tonic's graceful connection drain, bounded by an internal grace period (`server.rs`) — without that bound, a client sharing the same single-threaded async runtime as the caller (e.g. an unadorned `#[tokio::test]`) can deadlock it, since draining needs that same thread. Integration tests use `#[tokio::test(flavor = "multi_thread")]` to avoid relying on that fallback.
